## 1. 本轮目标与范围

把内置学堂做成一份可读、可玩、可复用的入门作品：用户在实际画布中，完成“看清一个问题—连接几条线索—回到原始资料—形成自己的判断”。

主标题：**织见学堂**。
副标题：**把散落的线索，织成自己的理解。**
首页短句：**先带着一个小问题进来。我们一起把它看清。**
保留品牌落款：织连万象，见聚一隅。

必须交付：重写学堂内容和画布、真实离线示例资料、安全升级机制、AI skill 实际调用与问题修复、回归验证、L1.3 安装版与便携版。

不扩大为整体 UI 重设计；不加入未获确认的模型接入、聊天面板、OCR、云同步或协作系统。学堂不是功能清单的图形化排版，也不应成为开发版本流水账。

## 3. 教学结构：九张画布，两条阅读路线

快速路线：00 → 01 → 02 → 03 → 05，约 8–12 分钟；仅为设计目标，不作为已测事实。
深入路线：04 → 06 → 07 → 08。各画布均能独立阅读。

共同结构：一句引入 → 一个可直接操作的例子 → 一个明确的小任务 → 一句观察结果 → 一个继续探索入口。
“试一试”使用普通可操作元素和简短文字，不默认开发自动判题、积分或闯关引擎。

### 00 · 从一个问题开始

目的：30 秒理解设计理念，知道下一步做什么。

首屏正文示例：
> 你有没有这样的时候：资料存了很多，真正要做判断时，却想不起哪一条能用？
> 在织见里，先放下一个问题。把观点、便签和原始资料围在它身边，再用连接说清它们的关系。
> 需要全貌，就退后一步；需要证据，就走近一点。

示例中心问题：“周末，我们办一场什么样的读书会？”周围仅 4 个对象：想法节点、待确认便签、实际 MD 附件、支撑关系。
试一试：选中“为什么想办读书会”，按 E 打开详情，再按 E 收起。
观察：标题让人知道这里讲什么，展开后才是完整内容，不需要把全文塞在画布上。
首页提供“从头体验”“我想找资料”“我想了解 AI”三个真实跨画布跃迁入口。不要把只是文字的便签画成按钮。

### 01 · 看全局，也看眼前

目的：区分聚焦、凝视、纵览、就地展开、全屏，避免混用术语。

用同一组 6–8 个元素演示：
- **聚焦 F**：围绕选中对象看关联，其余内容退为背景；不是删除或搬走其他元素。
- **凝视 G**：回到选中对象附近的适读尺度。具体缩放行为以当前实现为准。
- **纵览 Y**：重新看到整张画布。
- **展开 E**：节点看详情，附件看原文，尽量保持上下文。
- **全屏阅读**：给长文更多空间，使用实际可见的全屏入口；不要混淆窗口全屏与附件阅读全屏。

短文案：“图太大时，不必一直放大缩小。先选中你关心的那个问题。”
试一试：选中“场地怎么选”→ F → 退出聚焦 → E → 收起 → Y。
观察卡：“聚焦改变注意力，展开增加信息，纵览找回方向。”
实现者实际核对快捷键和退出行为后再冻结文案。

### 02 · 让连接说人话

目的：理解四类不同关系，不把所有线当成父子线。

用真实例子区分：
1. 层级：“活动筹备”下面有“场地”“选书”“报名”。表示拆解。
2. 归属：把“待确认噪音限制”便签关联到“场地”。表示这条材料归谁使用。
3. 语义连线：表示两项内容间的判断。
4. 跃迁：从总览跳到详细画布。表示到另一处继续阅读。

五种语义都要出现，但不要画成五角星式堆线：
- 关联：选书 ↔ 参与者兴趣。
- 支撑：参加者偏好小组讨论 → 支撑 → 采用小组形式。
- 导致：场地提前关闭 → 导致 → 缩短活动时长。
- 反证：候选场地周末施工 → 反证 → “这里足够安静”的判断。
- 证据：场地说明中的明确条款 → 证据 → 场地容量上限。

试一试：连接一条支撑关系，给它写一句“为什么”；改变方向后观察意思是否改变。
收尾：“连接之前问一句：我画的是分组、归属，还是一个有依据的判断？”

### 03 · 那句话，原来在这里

目的：完整教授 L1.1–L1.2 搜索，不重演旧混搜行为。

准备关键词“夜读”：分别放在节点标题、节点详情、便签、批注、MD 正文、PDF 第 2 页、第二张案例画布中。另放一个项目资料库未上画布的附件，用于展示范围区别。

三个分类：元素 Ctrl+F；便签与批注 Ctrl+Shift+F；附件 Ctrl+Alt+F。
范围：默认当前画布；切为当前项目才包含其他画布和项目资料库。
试一试：搜“夜读”→ 用 ↑↓ 切换 → 改分类 → 扩大范围 → Esc。
观察：被搜到的内容自动定位；搜索临时打开的内容会恢复；原本已展开的仍保持展开。
明确边界：扫描件和图片未接入 OCR；不能提取的资料会列出，不能把没有结果解释为文件里绝对没有这句话。

### 04 · 一句话，也带着来处

目的：把附件、摘录、引用位置、导出和恢复串成工作流程。

真实离线样本：`夜读场地说明.pdf`（2 页，可选文字）、`活动笔记.md`（含标题、列表、加粗和链接）。
试一试：打开 PDF 第 2 页，选一句话→摘录→便签“查看来源”→回到原页；再通过资料“使用位置”查看引用。
旁注：“摘录留下你关心的一句，来源让你随时回去核对。”
用两张小卡解释：
- 导出整个项目：适合带走相关画布和资料。
- 只导出当前画布：范围之外的跳转可能需要重新关联。
恢复中心介绍为“把历史版本恢复成副本”；不要写成“任何误操作都能无条件恢复”。

### 05 · 案例：把一场夜读办起来

目的：把前面的单项练习连成一个完整过程，普通用户也看得懂。

明确标注：**虚构教学案例，不代表真实调查。**

起点：“8 位朋友，90 分钟，怎么让每个人都愿意开口？”
画布分四段：想达成什么 → 手里有什么 → 冲突在哪里 → 暂定方案。
材料约定：场地最多 10 人；营业到 21:00；周六有施工；部分参加者周日有空。所有数据写入随包材料，全文与画布保持一致。
成品结论：“优先考虑周日，分成两组讨论；场地时段仍需确认。”最后一条刻意保留待核验便签。
小任务：“如果人数增加到 14 人，哪条判断先需要重看？”用户应沿证据和限制找到容量，不靠猜。
附一个可直接继续修改的练习副本入口；如果没有现成复制入口，提供现有导出/导入步骤，不擅自新增无效按钮。

### 06 · 案例：一个判断，够不够稳

目的：展现研究与分析价值，避免变成行业宣传或伪专业投资建议。

虚构题目：“街角书店值得延长晚间营业吗？”
提供 3 份自洽资料：一周分时客流 CSV、访谈摘录 MD、值班约束 PDF。
结构：支持依据、反对依据、尚缺证据、暂定结论；至少一处反证、一条来源引用和一条可播放的阅读路径。
示例结论：“先试行两周，再根据新增收入和人员成本决定。”这属于案例中的推断，不宣称是真实经营建议。
小任务：“删掉一份证据后，哪些结论应降低把握？”从“资料使用位置”反查受影响的对象。
附“迁移到你的工作”：读书笔记、课题梳理、产品调研、项目复盘；只列一句转换方式，不再另建四张画布。

### 07 · 请 AI 帮忙，也让它交代清楚

目的：讲清已存在的两条 AI 路线及核验责任。

路线 A：外部 agent 读取 skill，在已连接且可操作的应用环境中，通过 ZhijianAI 接口辅助建图。
路线 B：把 .fantin 和指引交给 AI，读取结构与实际附件，整理有来源的报告。

不能写：“点一下，织见内置 AI 自动完成研究”；当前不是内置聊天产品，也不是所有 AI 都能直接控制桌面画布。

可复制任务示例：
> 请把《活动笔记》整理为目标、约束、待办三个部分。每个判断关联对应材料；不确定的内容放便签，不要补造资料里的事实。完成后检查关系方向，并告诉我哪些信息还没有核验。

核验三问：“原文真的这么说吗？”“这条线方向对吗？”“哪些只是待验证的想法？”
用一个小错误案例展示：AI 把“周六施工”连成“支撑安静场地”，让用户发现并改正。明确标注“故意设置的练习错误”，不要把它混入成品参考答案。
介绍来源信息卡与真实附件的区别；来源卡写了名字，不等于原文件已被导入。
技术协议、命令名及 persisted 放到可展开的“给进阶使用者”附件；普通主线不出现 JSON。

### 08 · 现在能做什么，下一步想做好什么

目的：建立准确预期，不延续开发流水账。

三栏状态必须分开：
- **现在可用**：画布与语义连接、就地阅读、分类搜索、PDF 摘录来源、资料引用位置、阅读路径、导入导出和恢复、AI 接口与 skill。
- **仍有边界**：OCR/音视频转写未接入；部分格式只能显示提取文字；首次全文索引需要时间；大画布仍有性能优化空间；agent 环境决定能否实际控制应用。
- **后续方向，未承诺排期**：界面与布局一致性（用户已提出）、大画布和大资料集体验（建议方向）、更多原文定位覆盖（建议方向）。OCR、协作、云同步如提及只能放“待评估”，不得当成已批准路线图。

落款：“工具替你保留线索，判断仍由你来做。”
产品版本读实际应用版本；内容版本、更新日期单独记录，不凭空生成开发历史。

## 4. 视觉与文案规则

方向：**一份有留白的互动读本**。温和、清晰、有编辑感；趣味来自可验证的小任务，不来自大量表情、拟人提示或游戏奖励。

- 沿用现有主题、字体、圆角和色彩变量。不得为学堂强行修改用户全局主题、字体、背景偏好。
- 主色使用现有蓝；绿色表示已确认，暖黄表示练习/待确认，紫色少量用于延伸阅读。所有状态同时配文字，不能只靠颜色。
- 每张首屏只强调 1 个问题、1 组演示和 1 个动作。默认不展开一堆附件。
- 标题建议 6–14 字；节点正文标题不超过两行；操作提示一张卡 30–70 字；详情通常 120–300 字。超出时拆成新的可阅读层，不用缩小字号解决。
- 常规页面 8–14 个核心可见对象，案例约 12–20 个；这是密度目标，不是硬编码 API 数量上限。
- 画布优先 3 个阅读区域：左侧引入、中间操作、右侧观察；案例可采用横向论证路径。用真实节点和便签分区，避免大背景框挡住连线。
- 标题/区域间距建议 32–48 画布单位，普通元素间 20–28；实际以 100% 及适读缩放截图为准。
- 首页首次相机只展示开始区域，不把整张九宫格硬塞入窗口。每张画布设置独立合理相机，不每次切换都强行纵览。
- 装饰线、装饰图片不是语义连线；语义线必须能用一句话解释。只有 related 无向，其余核对方向。
- 适配 1440×900 与 1280×720，检查 100%/125%/150% 系统缩放和浅深主题。显示器实际测试条件记录在验证报告，不把未测组合算通过。
- 优先用现有节点、MD、轻量 SVG；本轮不要求生图、不增加外部字体和联网依赖。

禁止文案：“赋能认知”“知识宇宙”“全能 AI”“一键洞察”。用具体动作替代：“找到来源”“把这条证据连过去”“这里还缺一份资料”。

## 6. AI skill 实际使用与检验流程

### 6.1 环境与调用边界

在隔离用户目录中运行当前应用，读取本项目 SKILL.md、API 与 schema；记录 capabilities 和初始 snapshot。不要操作真实用户工作区，不删除真实项目。

通过应用同页上下文或现有 Electron 测试框架调用 `window.ZhijianAI`。先做首页试点，再扩到其他章节。

```js
const api = window.ZhijianAI;
const caps = api.capabilities();
const before = api.snapshot();
const result = await api.execute({
  op: 'build_canvas',
  requestId: 'tutorial-l13-welcome-v1',
  plan: {
    projectId: sandboxProjectId,
    title: '从一个问题开始',
    arrange: false,
    nodes: [
      { key: 'question', title: '周末办一场什么样的读书会？', x: 120, y: 100 },
      { key: 'format', title: '小组讨论', parentKey: 'question', x: 450, y: 100 }
    ],
    notes: [
      { key: 'pending', text: '还有几位朋友没确认时间', x: 450, y: 240, attachTo: 'format' }
    ],
    relations: [
      { from: 'pending', to: 'format', type: 'related', annotation: '时间会影响分组安排' }
    ]
  }
});
if (!result.ok || !result.persisted) throw new Error(result.error || '未完成持久化');
const after = api.snapshot();
// 使用 result.value.aliases 核对实际 ID、层级、attachIds 和关系；不能只看 ok。
```

这是可执行设计示例，`sandboxProjectId` 必须先通过 create_project 的实际结果获得，不可硬填猜测 ID。正式学堂标题与文案采用本方案。

### 6.2 需要具体检验的 skill 风险

| 检验 | 成功标准 |
|---|---|
| 文档中的完整 JSON 示例 | 原样执行成功，所有端点和 key 有定义 |
| 异步结果 | await 后检查 ok、persisted，并复读验证 |
| 手工设计布局 | arrange:false 后保留布局；不能调用完 autoLayout 又宣称执行了设计坐标 |
| 多根节点 | 验证是否自动插入根，避免装饰标题产生意外层级 |
| 五类语义与反向关系 | 类型正确，方向正确，反向有向线不误合并 |
| 便签、材料归属 | attachIds 有对应实际元素，不用 related 替代归属 |
| 真实附件 | 先经原生导入/受控教学资料安装写入 Blob，再用 fileId 关联；不能用来源卡冒充附件 |
| 重试与失败 | 同 requestId 不重复创建；非法端点/批量中途失败不留下半张学堂 |
| 跨画布跳转 | 先创建所有画布，取得返回 ID 后二次写入跳转；重启与导入后仍可用 |
| 报告读取 | 导出最终学堂，解析 data.json 并实际读附件；报告覆盖清单无无声遗漏 |

完整建图走 skill/API。应用 bootstrap 的 Blob 安装、内置项目标记、版本迁移属于产品实现，可以写应用代码，但不能拿直接改 state 冒充 API 建图成功。

现有 API 对 sourceRef、阅读路径等字段的写入能力需要实施者进一步实测。如果缺接口：先记录能力缺口；原生摘录/阅读路径功能可作为教学操作与功能测试使用。只有最终可重复构建确实需要时，才补最小、带校验的 API 支持，并同步文档和测试。不要一次性开发新的 AI 系统。

### 6.3 skill 修复与发布

修复项目内权威文档和解析器，再运行 `scripts/build-ai-guide.cjs`。核对生成的应用指引、托管 manifest、安装包内 skill 三者一致。保留用户定制 skill；沿用现有托管升级机制，不无条件覆盖个人修改。

提交一份 `L1.3-AI-skill验证记录.md`：每个问题写清“输入—预期—实际—修复—复测”，附必要命令与 snapshot 差异。没有实际运行过的项标记未测。

## 7. 安全升级学堂：本版必须完成

这是必要修复，不是可选优化。

建议固定身份 `builtinKey: "weavision-academy"`，另设 `tutorialVersion: 21` 或其他新值；实施前检查实际最新值，避免撞版本。用户名称、随机项目 ID 与内容版本不要混成一个字段。

升级行为：
1. 无学堂：待资料 Blob 与结构准备齐全后安装新学堂。
2. 已有同版本：直接复用。重启不得重建、不得新增重复项目、不得重置用户在学堂中的练习。
3. 旧版本：先建立可恢复记录；完整保留原项目及其 ID，将其标记为旧版练习副本，安装新学堂为独立项目。不要通过重命名破坏外部跳转；可增加版本后缀帮助辨认。
4. 普通用户项目恰好叫“织见学堂”或“知见学堂”：不得识别为内置学堂，不得改名或删除。
5. 附件写入失败/空间不足/迁移中断：不提交“新版已安装”标记，不删除旧项目；下次可重试。
6. 用户正在普通项目中：升级后保持当前项目和画布，不强行跳到学堂。首次新安装才默认进入首页。

推荐流程：唯一安装事务/锁 → 读取版本 → 准备新数据和 Blob → 写入附件并等待提交 → 原子提交结构和版本 → 仅在成功后更新显示。失败时清理本次产生的孤立附件，不碰既有资料。根据现有 IndexedDB 结构选择单事务或带安装日志的两阶段提交，不留半成品。

不得在启动代码中未经判定就 filter 掉旧项目。不得用 tutorialVersion 更新掩盖丢失用户练习。

## 9. 验收标准

### 内容与体验
- 九张画布各有一个清楚问题、一个可操作示例和一个能观察结果的任务；首页 100% 或默认适读尺度能看清“从哪里开始”。
- 设计理念、聚焦类、连接类、搜索、资料来源、AI、两个案例、现状及规划均覆盖。
- 普通阅读路径不要求理解 API、JSON、typed relations 或 Electron。
- 样例事实自洽；每项证据都能回到真实随包资料；演示错误与标准案例明确分开。
- 不存在失效按钮、悬空跳转、必须联网才能看的关键材料。

### 搜索与预览
- 三类搜索互不混淆；当前画布与当前项目结果正确。
- 按 ↑↓ 连续切换、Esc、点关闭、改关键词、跨画布：临时展开与邻近布局恢复；预先展开的保持原状。
- MD 搜索高亮复用正常预览；PDF 命中第二页能定位并高亮；不支持格式清楚说明。

### 数据与升级
- 同版本启动 3 次后，项目数、画布数、核心 ID 与附件数不增加。
- 用户在旧学堂加一张便签后升级，旧内容仍完整可用；普通同名项目不受影响。
- 普通项目当前选择与全局主题偏好不被学堂安装改变。
- 模拟附件写失败与结构写失败，不出现半安装的新学堂，不丢旧数据。
- 最终学堂导出/再导入：真实附件、层级、归属、语义方向、来源、阅读路径与跨画布跳转经核对。

### AI skill
- 文档完整示例实际可运行。
- 九张画布的建图证据来自真实 API 返回与复读 snapshot，不是手写“测试通过”。
- 至少验证一次非法引用回滚、一次幂等重试、一次反向有向关系。
- `.fantin` 报告阅读流程检查真实附件覆盖；来源卡不能计为已读原文件。

保留并运行与改动有关的现有 tests/l1-search.cjs、l1-integration.cjs、l1-migration.cjs、k6.test.cjs；根据新学堂新增 tutorial-l13 专项测试。旧测试若因教程数据数量假设失效，修改为校验性质，不硬凑数字。
