## 0. 文档用途

把"织见 + 投× + 行业观点"这一整套内容怎么推广、怎么设计，固化为一份可交接的规划。目标有三个：

1. 拓宽用户群体。
2. 三个内容方向形成**叠加效应**而不是各自为战，避免关注者因内容不相关而取关。
3. 顺带赚点小钱。

## 3. 统一人设与内核

### 3.1 人设

**"一级投资经理白天工作、晚上 coding/创作之路"** —— 白天做投资（看 BP 筛项目、尽调），晚上搞 coding 和创作。

### 3.2 内核（一句话）

**主轴不是"我做了一个工具和一个游戏"，而是"我怎么拆解投资这个行业"。**

- 行业观点 = 拆解的直接输出
- 织见 = 拆解的理性工具化（观点变成能用的东西）
- 投× = 拆解的讽刺故事化（观点变成能体验的世界）

三者是同一个内核的三种密度，不是并列三块。

### 3.3 海外人设（英文版）

"an investment professional who builds tools and games to decompose the industry"

多领域创作者身份在海外 indie 圈很吃香。

## 4. 叠加效应设计（避免取关）—— 核心

### 4.1 问题

关注者如果看到三块当成"三个不相关兴趣"，就会出现"今天为游戏而来、明天看到行业观点觉得无聊就走"。需要三线形成叠加，不是各自为战。

### 4.2 解法

重新定义三块关系：主轴 = "你怎么看投资这个行业"，工具和游戏是观点的两种物证形态，不是并列三件事。关注者收到的是一条连续的认知流，工具和游戏是这条流上的两个物证。

### 4.3 叠加规则（执行 agent 写每条内容时遵守）

- 每条内容尽量挂上"内核"标签，让关注者知道这都是同一个人对投资行业的拆解。
- **内容交叉引用：**
  - 发行业观点时 → 偶尔带织见截图 / 投×角色原型
  - 发投×设定时 → 点明"这来自真实行业观察"
  - 发织见演示时 → 用真实投研案例
- 每条内容都在加深同一个认知，而不是切换频道。

### 4.4 边界红线（避免取关）

- **不发跟"拆解投资行业"无关的内容**（纯日常、跟投资无关的 coding、纯生活分享）——这些会稀释人设、触发取关。
- 人设是"投资经理 + 创作者"，不是"全栈博主"，边界要清晰。

## 9. 平台机制注意（为什么抖音/小红书都不直接贴链接）

### 9.1 现象

抖音、小红书上分享应用的内容创作者都不直接贴链接，而是私信发或不说清楚。

### 9.2 原因（平台规则决定，不是创作者不懂）

- 抖音、小红书对站外链接（尤其应用下载、GitHub、外部商城）有**强限流甚至判违规**。平台要留住流量，防导流到站外。
- 公开内容贴链接 → 限流；评论区贴 → 可能删评；简介贴 → 部分被识别降权。

### 9.3 创作者用私信发/不说清楚的三个原因

1. **规避风控** —— 私信里放链接比公开内容更不容易触发限流检测。
2. **逼互动** —— 用户想拿链接就得评论、就得私信，这些互动数据反哺算法推荐。
3. **导私域** —— 把公域流量先沉淀到微信/公众号/群里，再在私域做转化和复购（国内"私域引流"标准打法）。

### 9.4 对织见/投×的启示

- 抖音/小红书**不能指望在视频里贴 GitHub 链接**。要么走私信发链接，要么导到一个中转（公众号回复关键词自动发下载地址）。
- **织见"可分发文件"卖点在这里形成传播协同**：别的工具在抖音只能偷偷私信一个下载链接，转化低；织见的产物本身是可分发文件，可以直接在私信里发一个织见文件，对方打开就是完整的、带勾稽关系的内容板，不是一张截图也不是冷冰冰的安装包。**产品即内容即传播载体**——这是 Obsidian 这类工具做不到的（它们没法把一个带双链和关系的板直接发给没装软件的人看）这个角度值得作为内容里反复出现的钩子。
- **B 站是唯一能光明正大贴 GitHub 链接的主平台**，所以织见的下载转化以 B 站为主。

## 10. 变现路径

### 10.1 织见

- 法律上：用户作为版权人可自行商用（Pro 版/SaaS/托管/付费增值功能/双授权/定制服务均可），不受自己 license 约束。
- **实际判断（用户）：织见变现较难，定位为展示/引流/扩大推广，变现次要。**
- 可行的织见变现形态（用户授权给自己商用）：
  - Pro 版 / 付费增值功能（开源核心免费，高级特性付费）

  - 升华收束（"说到底这三样是一回事"这种——必要时可用，但别每段都升）
